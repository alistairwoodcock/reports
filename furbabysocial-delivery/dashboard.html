Security Work Beyond the Findings

Appello's access removed
Agency AWS users and keys deleted, the open photo-storage policy removed, the database password changed, and user reports no longer emailed to Appello.
Servers closed to direct access
The API servers accepted traffic straight from the internet, bypassing the load balancer. Now load balancer only.
Least-privilege access
Production runs with its own limited permissions instead of an agency admin key. Admin access to AWS uses two-factor sign-in.
Privacy
Other users' phone, email, birth date and postcode are no longer sent to the app. Personal data is kept out of logs.
Account suspension
Suspended users are locked out on every device straight away.

Performance & Scalability

Improvements

Slow services no longer hold up the app
Push notifications, SMS, photo storage and Firebase calls now run off the main request path, so one slow service can't stall everyone.
Database indexes
Indexes added for feeds, profiles, friends, comments and notifications; 13 duplicate indexes removed.
Runaway feed requests
An empty feed made each phone ask the server about 50 times a second. Fixed.
Faster, smaller images
Photos are resized on the phone before upload and served at screen size through an image CDN.
Less server work per request
Reusing one storage connection cut about 60% of the server's processing per request under load.
Live updates can't break posting
A realtime-server hiccup no longer makes likes, comments or posts fail.

Beyond the Quote

Problems found along the way that had to be fixed for the app to work, plus the post-launch improvements recommended in April.

Kept the App Running

App Store outage
Since July the App Store app couldn't connect. Its security pins broke when the server certificate renewed. Fixed from 3.2.4 on.
Chat and push restored
Appello's Firebase project was deleted. A new one was set up, users moved across, push keys renewed.
Live updates
Moved to an encrypted connection; they now work on Android for the first time.
Store requirements
Android 16 target and 16 KB memory-page support, both required by Google Play.
Android launch crash
Crash reports showed the Android app closing at start on Intel-based devices such as Chromebooks. Reproduced, fixed and confirmed in 3.3.0.

Running the Platform

Staging environment
Changes are tested on a copy before going live. Switches off overnight to save cost.
Monitoring and alerts
8 alarms email us if the server, live updates or database have problems. The database can't be deleted by accident.
Admin panel
Admin login, a Reports screen, and moderation: delete posts and comments, suspend or reactivate users.
System documentation
Architecture, runbook, account inventory and incident checklists.
